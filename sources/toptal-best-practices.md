# Toptal profile and pitch best practices

Actionable rules for Toptal profile enhancement and job-application pitches in this repo. Each rule lists **Why**, **Source IDs** (see [toptal-references.json](toptal-references.json)), and **Anti-patterns**.

## Source priority (read in this order)

1. **Priority 1 — official PDF extracts (required)**
   - [toptal-guides/job-application-matching-handbook.md](toptal-guides/job-application-matching-handbook.md) ← `toptal-matching-process-pdf`
   - [toptal-guides/developer-profile-creation-guide.md](toptal-guides/developer-profile-creation-guide.md) ← `toptal-profile-creation-guide-pdf`
2. **Priority 2 — public Toptal web sources** (supplemental; defer to handbook when rules conflict)

When the Career Center resume summary suggests longer prose but the matching handbook specifies **500 characters** for pitches, **follow the handbook**.

## 1. Voice and tone

### Rule: Write in third person without pronouns

**Why:** Official handbook requires third person in application questions and strong examples; weak examples use first person. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Using "I", "my", "me" in pitches, application answers, or profile bio
- Switching between first and third person
- Overly casual openers ("Hi Sir!")

### Rule: Be clear, concise, and free of buzzwords

**Why:** Weak applications are vague, repetitive, and grammatically poor; strong ones are specific and client-focused. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`, `toptal-top-3-percent`

**Anti-patterns:**
- "Team player", "go-getter", "passionate" without evidence
- Keyword dumps
- Promising to "win against anyone else"

## 2. Profile bio and platform profile (baseline enhancement)

### Rule: About paragraph ~three sentences, third person, client-focused

**Why:** Matchers paste About text when introducing talent; profile guide specifies ~3 sentences in third person with client-first framing. [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-profile-creation-guide-pdf`

**Anti-patterns:**
- Long bios when ~3 sentences are expected
- First person in About
- Generic opening without notable achievement or scale

### Rule: Include a “most amazing…” pride statement

**Why:** Profile guide requires a specific real project that made you proud — clear, detailed, non-generic. [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-profile-creation-guide-pdf`

**Anti-patterns:**
- Generic pride statements not tied to verified work

### Rule: Work experience bullets — 3–10 per role, 50–250 characters, quantified

**Why:** Profile guide specifies accomplishment bullets with past-tense active verbs and outcomes — not duty lists. [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-profile-creation-guide-pdf`

**Anti-patterns:**
- “Developed a website” without scope or outcome

### Rule: Rate skills Competent, Strong, or Expert — do not oversell

**Why:** Profile guide levels; first 15 skills feed About tags; up to 8 highlighted in Expertise. [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-profile-creation-guide-pdf`

**Anti-patterns:**
- Expert on every skill; unrelated expertise highlights

### Rule: Connect every skill to a job or project in the profile

**Why:** Matchers search by skills and validate them against profile work history before pitching talent to clients. [toptal-matching-process-pdf] [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-matching-process-pdf`, `toptal-profile-creation-guide-pdf`

**Anti-patterns:**
- Skills listed with no linked project or employment entry
- Skills comprehensive but disconnected from evidence

### Rule: Work experience must match profile skills

**Why:** Matchers use work history to validate skills and pitch fit. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Chronological duty lists without problems solved
- Long tenures without organizing by initiative, project, or role

### Rule: Minimum 5 portfolio projects for developers

**Why:** Official handbook specifies developer minimum; matchers and clients review portfolio closely. [toptal-matching-process-pdf] [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-matching-process-pdf`, `toptal-profile-creation-guide-pdf`

**Anti-patterns:**
- Fewer than 5 developer portfolio entries when evidence supports more
- Projects without links or clear individual contribution

### Rule: Link external profiles (GitHub, LinkedIn, personal site)

**Why:** Clients like work descriptions and samples; increases credibility. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Missing GitHub when indexed repos exist
- Broken or placeholder links

### Rule: Professional headshot per profile guide (1000×1000+, business casual)

**Why:** Profile guide requires high-resolution shoulders-up photo, neutral background, natural color, no filters. [toptal-profile-creation-guide-pdf]

**Source IDs:** `toptal-profile-creation-guide-pdf`, `toptal-matching-process-pdf`

**Anti-patterns:**
- Filters, casual attire, group photos, low resolution

### Rule: Professional photo and accurate availability/overlap

**Why:** High-quality photo increases hire chance; overlap and availability must be honest and up to date. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Claiming overlap you cannot sustain
- Stale availability blocking applications

## 3. Job application pitch

**Basis:** All pitch generation must follow [job-application-matching-handbook.md](toptal-guides/job-application-matching-handbook.md) **§10–12** (goals, focus, wow factor, questions to answer, strong/weak patterns) before writing.

### Rule: Pitch goals — matchers, profile hook, interviews

**Why:** Handbook §10 — pitches attract matcher and client attention, hook clients to read the full profile, and increase interview chances. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Generic self-summary with no client hook
- Pitch that reads like a cover letter with no clear “why you for this job”

### Rule: Client-focused pitch addressing specific job requirements

**Why:** Handbook §10 — **focus** is the biggest difference between poor, good, and outstanding pitches; understand client needs from JD and **research company/culture** when possible. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Generic pitch reusable across unrelated roles
- Restating entire CV chronologically
- Experience too wide to be relevant to the position (see §12 Brand/Web Designer weak example)
- Unrelated stack or domain stories when JD is narrow

### Rule: Target ~500 characters for the main pitch (wow-factor guideline)

**Why:** Handbook §10 — outstanding pitch "tells a story in **500 characters or less**" while balancing overview with impressive details. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Multi-paragraph cover letters when a focused pitch is requested
- Over 500 characters when the form is character-limited (check JD/form)
- Under ~300 characters with no project links or proof

**Note:** Some application forms allow a longer paragraph. If the form has no character limit, prefer handbook focus and density over length; stay under ~120 words unless the form clearly invites more.

### Rule: Structure — fit → depth in industry/skill → value with links/stats → enthusiasm

**Why:** Handbook §10 — detail depth in client industry, relevant skill, and solving similar needs; personal story with specific examples; links, statistics, results, numbers; enthusiasm for project type. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Projects mentioned without links when public URLs exist
- No quantifiable results where verified metrics exist
- Burying strongest evidence in the last sentence
- Listing duties instead of client value

### Rule: Answer handbook “strong pitch” questions from verified evidence

**Why:** Handbook §10 question table — weave where, what you built, recognition, scope, expertise, and identity into a focused story for **this** JD. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Weave when verified (prioritize JD-relevant items):**

- Industries, company types, company sizes; name well-known brands when accurate
- What you created — scale (users, budget, aggregate scope) and results
- Years of experience; specialty and most expert areas (projects, methods, technologies)
- Most notable achievement; what makes you stand out
- Industry experience even if past roles differ — **lead with impressive industry proof when it fits**

**Anti-patterns:**
- Answering every handbook question in one pitch (loses focus)
- Vague “many apps” or “full experience” without specifics (see §12 iOS weak example)

### Rule: Rank and qualify skills honestly in pitch

**Why:** Strong Python example (§11) notes JavaScript experience but clarifies "definitely not an expert" — honesty builds matcher trust. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Claiming expert level for peripheral skills
- Hiding gaps in pitch (document in match report instead)

### Rule: Show why this project specifically — passion when genuine

**Why:** Strong Python example (§11) ties fit to robotics passion and similar consulting work. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Generic enthusiasm without domain link (“amazing project for my skill-set”)
- Passion claims with no evidence

### Rule: Include availability, overlap, and interview timing when JD asks

**Why:** Strong Python example (§11) addresses part-time→full-time transitions, overlap hours, and interview windows concretely. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Omitting overlap commitment when JD specifies client hours
- Vague availability ("flexible") without hours

### Rule: Strong-application voice — third person, grammatical, no filler closings

**Why:** Strong Salesforce example (§11) is third person and error-free; weak iOS example (§12) is first person with unnecessary closing promises. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- "Hi, Sir!" or other casual openers
- First person ("I am…", "my", "me")
- Closing paragraph promising to "win against anyone else"
- Spelling/grammar errors

## 4. Application questions

### Rule: Answer in third person; reference pitch when redundant

**Why:** Handbook explicit rule; good answers are specific with metrics; bad answers are first-person and vague. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

**Anti-patterns:**
- Repeating pitch verbatim instead of "added in the pitch."
- First-person answers ("I am a leader…")

## 5. Application timing and status

### Rule: Apply early based on Job Hiring Status

**Why:** Best time is when no interviews started; after candidates introduced, apply ASAP; once client interviewing, new apps less likely. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

### Rule: Respond to Job Interest Requests within ~8 hours when interested

**Why:** Matchers send profiles within 24 hours of posting. [toptal-matching-process-pdf]

**Source IDs:** `toptal-matching-process-pdf`

## 6. Evidence and honesty

### Rule: Never invent employers, projects, metrics, or skills

**Why:** Matchers validate skills against profile; integrity aligns with Top 3% bar. [toptal-matching-process-pdf] [toptal-top-3-percent]

**Source IDs:** `toptal-matching-process-pdf`, `toptal-top-3-percent`

### Rule: Flag gaps in match reports, not in the pitch (unless user asks)

**Why:** Pitch sells verified fit; gap analysis belongs in `pitch-match-report.md`.

## 7. Checklist — pitch ready to paste

Handbook §10 “wow factor” + §11 strong patterns:

- [ ] Third person throughout (no I/my/me) — not weak §12 iOS style
- [ ] Client-focused — addresses **this JD’s** specific requirements (focus = biggest quality lever)
- [ ] Shows **why this project specifically** is a good fit
- [ ] Depth in client **industry**, **relevant skill**, and **similar needs**
- [ ] Personal story with **specific examples** — not vague “many projects”
- [ ] **2–3 projects** with [links](url); **statistics/results/numbers** where verified
- [ ] Skills **ranked and qualified** honestly (primary vs peripheral)
- [ ] One **notable achievement** or proud example tied to this engagement
- [ ] **Enthusiasm** for this project type (when genuine and evidenced)
- [ ] Value framing: “This is what I bring to **you**” — not “please hire me”
- [ ] ~**500 characters** if form is character-limited (check handbook)
- [ ] Optional skills only if evidenced — no experience too wide for the role
- [ ] **Availability/overlap/interview timing** when JD asks (§11 Python pattern)
- [ ] Grammatically clean — no spelling errors (§12 weak examples)
- [ ] Application questions answered in third person or "added in the pitch."
- [ ] Saved to job folder (not chat-only)

## 8. Checklist — profile ready to paste

- [ ] About: ~3 sentences, third person, client-focused, opens with strongest achievement
- [ ] “Most amazing…” statement: specific verified project, non-generic
- [ ] **5** portfolio projects with on-profile descriptions and direct project links
- [ ] Work bullets: 3–10 per role, 50–250 chars, quantified where verified
- [ ] Every skill connected to work experience, portfolio, education, or certification
- [ ] Skills rated Competent / Strong / Expert honestly; ≤8 expertise highlights
- [ ] GitHub, LinkedIn, personal site linked
- [ ] Headshot meets guide guidelines (or gap noted)
- [ ] Time zone, working hours, flexible hours accurate
- [ ] Gap report lists unsupported items
